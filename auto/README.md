# 格拉默脑机 v1.2 · 三角洲坐标自动化

> v1.0 定稿（2026-11-14）。功能冻结，改之前先看「## 版本与已知边界」。

基于 `src\标定程序\config.json` 里标定好的 16 个位置，跑「检测 → 分流 → 执行」的闭环。

```
                     ┌────────────────┐
                     │ 检测：读 3 余额 │
                     └───────┬────────┘
        ┌────────────────────┼────────────────────┐
   余额 < 30w            30w ~ 80w          > 80w 或出现 K
        │                    │                    │
   ┌────▼────┐         ┌─────▼─────┐       ┌──────▼──────┐
   │ A 卖货  │         │  B 抢购   │       │  报错暂停   │
   └────┬────┘         └─────┬─────┘       └─────────────┘
        └──────────┬─────────┘
                   ▼
              回到检测
```

## 程序界面（推荐入口）

双击根目录的 `启动.bat`，打开的是一个**独立程序窗口**——不是浏览器、没有地址栏、没有标签页。
前后端是分开的，界面改了不用动自动化逻辑，反之亦然：

```
启动.bat
  └─ server\main.py            开窗口（pywebview + 系统自带 WebView2）
       ├─ server\app_handler.py  本地 HTTP 服务，只对外暴露 /api/*

       └─ web\                   前端（HTML / CSS / JS），只认 /api/*
```

- **开始运行**：拉起 `dvc_auto.py --live`。这时候窗口会自动**缩成小窗并置顶**，界面切到精简模式
  （藏掉配置和说明，把日志让出来），方便边看边放。跑完自动还原原来的大小和层级。
- **读余额**：只读一次 3 号区域，不动窗口、不点击。**开跑前先用它确认识别没问题。**
- **置顶**：手动把小窗钉在最前并切精简模式，不用真的开跑。再点一次取消。
- **重新标定**：直接拉起 `src\标定程序\dvc_calibrate.py` 的全屏覆盖层，框完保存后自动回来重读 config。
  第 17 步是框「空白存储」物品格，截图直接写到 `auto\assets\blank_storage.png`，把内置模板覆盖掉。
  存没存是靠 `config.json` 的修改时间判断的（标定程序保存和放弃的退出码都是 0，不可用）。
- 按 **F9** 随时急停；关掉窗口就是退出程序。

每次启动窗口都摆在屏幕正中，大小按屏幕比例算（不写死像素，换分辨率不会变成一小坨）。

## 前置条件

1. **Python 3.8+**，且 `pip install numpy pillow`。缺库时程序不会甩 traceback，而是直接用中文告诉你缺什么、该跑哪条命令；也可以双击 `装依赖.bat`，或 `run.bat` 里选 12。
2. **新窗口版还要 `pywebview`**：`python -m pip install pywebview`。它靠系统自带的 WebView2 渲染，
   Win10 1803 以后基本都有（Edge 装了就有）。缺了启动时会直接把命令打在屏幕上。
3. **游戏必须是「窗口化」或「无边框窗口化」**。独占全屏下 Windows 不给 BitBlt 抓画面，程序会抓到全黑并报警（自检里会明确写出来）。
4. 屏幕分辨率 / 缩放要和标定 `config.json` 时一致。自检会直接告诉你「配置标定在 1920x1080，当前屏幕 3200x2000 —— 坐标会整体错位」。
5. 关掉一切可能吃掉鼠标的东西（远程桌面、录屏悬浮窗等）。

## 第一次使用

按顺序做，每一步都能单独验证。**推荐走新窗口**（双击根目录 `启动.bat`），下面括号里是等价的命令行入口：

```
1) 自检（run.bat -> 1，或窗口里点「读余额」时顺手看日志）。
   看三件事：DPI 模式、屏幕和配置是否一致、全屏抓取是不是「正常」。

2) 读一次余额，确认 OCR 结果和游戏里一致（窗口里的「读余额」，或 run.bat -> 2）。
   字模已经用 15 张样本图训好了（0-9 和 K 全覆盖，留一法 15/15 全对），
   正常不用再采。只有当某个数字经常认错时，才需要补：
   run.bat -> 3/4 补采，或者用 11 号入口从现成截图补。

3) 找物品图（run.bat -> 6）。游戏开到仓库页，看能不能命中、分数多少。
   分数 > 0.85 很稳；0.7~0.85 勉强；找不到就调 --threshold。

4) 空跑整个闭环（run.bat -> 7）。只打印不点击，确认流程顺序对。

5) 实盘（窗口里点「开始运行」，或 run.bat -> 8）。按 F9 随时急停。
```

## 命令

```
python dvc_auto.py --selftest       自检：DPI/坐标/截图/OCR/找图
python dvc_auto.py --probe --live   读一次余额并给结论
python dvc_auto.py --learn balance  采余额数字字模
python dvc_auto.py --learn price    采价格数字字模
python dvc_auto.py --ocr-live       持续打印余额/价格 OCR（30 秒）
python dvc_auto.py --find           在仓库区找物品图，看分数和耗时
python dvc_auto.py --dump ocr_price 把某个区域存成 png 看标定准不准
python dvc_auto.py                  空跑闭环（不点击）
python dvc_auto.py --live           实盘
python dvc_auto.py --only a --live  只跑 A
python dvc_auto.py --only b --live  只跑 B
python dvc_auto.py --rounds 1 --live 只跑一轮
```

调参：

```
--threshold 0.72      找图 NCC 阈值，调低更容易命中、也更容易误中
--step-delay 0.32     普通点击之间的间隔（秒）
--click-gap 0.025     高速往返点击 11/12 的间隔（秒）
--sell-hold 1.20      A 程序里「出售」确认键按住多少秒（长按才会生效）
--esc-quiet 1.00      按第一个 ESC 前先静置多久，给游戏时间收下上一次点击
--esc-gap 0.18        连按 ESC 的间隔（秒）
```

## OCR 验证工具

`ocr_probe.py` 用来单独验证「这块数字到底认不认得出、读得多快」，不碰鼠标键盘。
双击 `OCR验证.bat`，或者：

```
python ocr_probe.py                        拖框：在屏幕上按住左键圈一块
python ocr_probe.py --region ocr_balance   直接盯 config.json 里的余额区域
python ocr_probe.py --region ocr_price     直接盯价格区域
python ocr_probe.py --box 2468,168,2610,209  直接指定坐标
python ocr_probe.py --png 图.png            离线认一张图，打印结果和耗时
python ocr_probe.py --png 图.png --once     同上
```

拖完框后窗口里会跟出一个浮层，实时显示：

```
(空)                          <- 识别结果，认不出是 ?，带 K/W/M 变黄
识别 0.28 ms  均 0.31  峰 2.05    60 次/秒
抓图 15.4 ms  区域 142x41  字 0  置信 0.00
F9 重选  F8 存图  ESC 退出
```

- **识别** = 模板匹配耗时；**抓图** = BitBlt 耗时；**次/秒** = 每秒完成多少次完整识别
- 浮层刷新约 14 次/秒，但上面的「次/秒」是真实采样频率，两者不一样
- `F8` 把当前帧存到 `debug\probe_时间.png`，认错时拿这张图补字模
- 浮层默认半透明。如果录屏软件抓不到它，设环境变量 `PROBE_SOLID=1` 再启动就变成不透明

参考值（192 DPI 下实测）：空白区域约 0.2~0.3 ms，6~9 位数字约 1~5 ms，
抓图固定 13~19 ms，所以整条链路 60~75 次/秒，瓶颈在抓图不在识别。

## 两条流程

**A：卖「空白存储」补余额**（余额 < 30w）

点 2 仓库页签 → 在 4 区域找物品图 → 点 5 购物车 → 点物品 → 点 6 出售 →
等 800ms 让出售弹窗出来 → 双击 7 确认 → 7 次 ESC → 点 16 回初始页 → 回检测。

> 这 800ms 是 `dvc_auto.py` 里 `DEFAULTS["sell_ok_delay"]`，弹窗出得慢就调大；
> 双击的两次间隔是 `DEFAULTS["double_click_gap"]`（0.09 秒），太大会被游戏当成两次单击。

> 找不到物品会直接暂停，不会瞎点。找图用的是 NCC（归一化互相关），
> 所以物品格被选中变亮、有描边也认得出；模板四周裁掉 10% 是为了躲开边框变色。

**B：刷价抢购**（30w ~ 80w）

点 1 配装 → 点 8 或 9 槽位（`config.json` 里 `options.target` 控制，默认 helmet）→
拖 10 滚动条到底 → 点 12、11、12 热身 → 进高速循环：

- 一个线程反复点 11、12（切两行选中态，逼游戏刷新最低行报价）
- 另一个线程盯着 13 区域做 OCR，每轮先睡 12ms 让画面追上这次点击
- 价格进 20w~30w 立刻停手

停手后点 12 确认 → 光标快速移到 14 停 10ms 点 → 移到 15 停 10ms 点 →
7 次 ESC → 点 16 → 读余额记变化，写 `purchase_log.jsonl`。

> 单次 OCR 实测 1.2ms（94x29 区域，模板匹配），往返点击一轮约 55~60ms，
> 所以真正卡速度的是点击间隔，不是识别。

## 为什么用模板 OCR 而不是 tesseract

「高速 OCR」要在点击循环里每秒读几十次。tesseract 单次 50~100ms，还没算进程/库的
启动开销，根本撑不住。游戏 UI 的数字是固定字体固定字号，把 0-9 的字模各采一张
（20x28 灰度图），识别就是一次矩阵点积，1ms 出结果，而且比通用 OCR 准。

采字模时如果切出来的字符数和输入对不上，说明数字粘在一起了或框偏了，
程序会直接报错告诉你差几个，不会将就着存。

## 常见问题

**自检说「全屏抓取：全黑/全同色」**
游戏在独占全屏。改成窗口化或无边框窗口化。

**自检说坐标会整体错位**
`config.json` 是在别的分辨率下标定的。重新跑一次标定程序，或者按比例调
`config.json` 里的 `screen.w/h`。

**OCR 读出来是空的 / 全是问号**
三种可能：框没框准（`--dump ocr_balance` 看一眼截出来的是什么）、字模没采全
（`--learn` 补齐）、游戏里数字颜色太接近底色。

**余额读出来带 K / 认不出**
程序会当 Fatal 暂停。这是按需求设计的：出现 K 说明金额显示方式变了，程序不该
瞎猜，停下来让人看一眼。

**找图分数 0.6 左右晃**
装备格有选中高亮，或者物品有叠放数量角标。先 `--dump scan_blank` 看实际画面，
再决定是调 `--threshold` 还是换一张更干净的模板图。

**点了之后游戏没反应**
有些游戏只认硬件层输入。`SendInput` 能过大部分游戏；如果完全没反应，说明这个
游戏挡模拟输入，这条路走不通。

## 注意

- 模拟输入 + 主动抢购，属于游戏规则里明确禁止的行为，账号风险自己承担。
- 程序默认 **dry-run**，不加 `--live` 不会点任何一下。
- F9 是急停，任何时刻都能停。
- 余额 > 80w 会自动暂停并响三声，防止把余额刷过头。

### 两个状态看的东西不一样

- **待机**：大数字是「当前余额」，用来判断这轮会走 A 还是 B。
- **工作态**（点了「开始运行」或「置顶」之后，窗口缩到 1/4）：大数字换成「当前最低价」，
  跟着高速刷价实时跳，落到 20w~30w 就自动买。底下那行小字会写「刷价中，落到 20w~30w 就自动买」。

价格是怎么传上来的：`dvc_auto.py` 的 `rapid_hunt()` 每读到一次价格就打一行裸的 `PRICE 268000`
（限流 150ms 一条，不进日志）。`server\engine.py` 用 `PRICE_RE` 把这行截走更新价格卡，
同一个价不重复广播；其余行照常走日志。

### 开跑前会先重置一次界面

点「开始运行」后、读余额之前，程序固定先做一遍「连按 7 次 ESC + 点击屏幕中央」，
把界面按回主状态。上一次可能停在仓库、配装页或者出售弹窗上，不重置就直接往下点，
第一下很容易点空。

不想要这一步就加 `--no-reset`（只影响命令行；界面上没有开关）。

## 抢购概况与抢购日记

界面上现在看的不是余额，而是这一轮要抢多少件、已经抢到多少件。

- **抢购概况**（左侧）：头盔、护甲各一行，`已抢 / 目标`，目标数字直接改，改完自动记住。
- **成交价**：最近一次抢到的价格。
- **抢购日记**（右侧标签页）：每抢到一件记一行，时间、头盔还是护甲、成交价、这是第几件。跟「运行日志」点标签切换。

窗口有两个形态，标题也会跟着换：

| 形态 | 什么时候 | 看什么 |
| --- | --- | --- |
| 待机（大窗） | 没在跑 | 抢购概况 + 配置 + 运行日志 |
| 工作（小窗置顶） | 点了「置顶」或者在跑 | 当前最低价（大号数字）+ 日志 |

## 抢购顺序

先抢头盔，头盔抢够目标数量后自动切去抢护甲；两样都够了就收工，日志里会写「头盔 x/y、护甲 x/y 都抢够了，收工」。

**只有余额真的掉下来了才算抢到。** 手慢或者被别人抢走时余额不动，这一下不计入已抢数量，日志里打一条 WARN 继续刷。

命令行等价写法：

```bat
python dvc_auto.py --live --helmet 3 --armor 2
```

`--helmet` / `--armor` 不给就用界面里存的数字。
